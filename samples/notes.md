# 现场记录

随手记的，别当规格看。

- 生成器是两年前同事写的，人调走了，脚本也跟着没了，只剩一批定义文件和上次生成的那几个文件。这次得从头写。
- 出事那天：他直接把刚生成的文件拷进目录，把手写在 `charge_card_impl` 里的重试逻辑冲掉了。线上问题临时加的那
  几行，没有分支、没有备份，从备份机里翻了一天，最后是在一台停用的构建机上找回来的。
- 从那以后定的规矩：手写的只写在 `>>> stubforge:hand` 和 `<<< stubforge:hand` 之间，生成区一个字都不许改——
  改了下一遍也会被覆盖。反过来说，谁要是手改了生成区，生成器应该看得出来（文件头里那个 `skel` 就是给这个用的）。
- 重生成最怕的就是「其实什么都没变，却把文件全重写了一遍」：审代码的人分不清哪些是真改动，`mtime` 一抖全变。
  没变化的文件就该一个字节都不动，连打开写都不要。
- 有回两个人各贴了一半定义，同一份接口字段顺序不一样、`optional: false` 有的写有的省，diff 出一屏；其实就是
  同一份，生成器得认出来。
- 字段名是从上游的 JSON 抄下来的，`class`、`from`、`id`、`type` 这种名字躲不掉；还有一份历史数据里同时有
  `card-id` 和 `card_id`。改成 Python 名字以后，得能反查回原来的线格式名。
- 交付前对方强调过：同一份定义跑两遍，清单和产物必须完全一样，方便逐行比对。
